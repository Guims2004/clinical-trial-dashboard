# Clinical Trial Compliance & Monitoring Dashboard

**Developer:** Olivia Ngueguim  
**Target Audience:** Institutional Review Board (IRB) Directors, Research Ethics Committees, University Research Administrators  


# 1. Project Overview

This project is a full-stack **clinical trial compliance monitoring system** that transforms raw clinical trial data into actionable insights using an automated ETL pipeline and an interactive dashboard.

It is designed to support oversight of clinical studies governed by regulatory bodies such as the FDA and Institutional Review Boards (IRBs).

The system integrates:
- Data extraction from structured datasets (ClinicalTrials.gov-style format)
- ETL processing and cleaning using Python
- A real-time interactive dashboard built with Dash and Plotly


## Problem Statement

Clinical trial data is publicly available but difficult to interpret due to:
- Large and complex raw datasets
- Inconsistent formatting across sources
- Lack of centralized monitoring tools

This project solves this by building an automated system that:
- Cleans and structures clinical trial data
- Tracks compliance and recruitment activity
- Visualizes trial distribution and sponsor activity
- Enables drill-down inspection of individual studies


# 2. Technology Stack

# 3. System Architecture (ETL Pipeline)

## 3.1 Data Sources
The system uses structured clinical trial datasets stored locally:

- `trials.csv`
- `enrollment.csv`
- `sponsors.csv`
- `locations.csv`


## 3.2 ETL Process

### Extract
- Load CSV datasets from the `/output` directory
- Simulated structured ingestion pipeline

### Transform
- Merge datasets using:
  - `nct_id` (clinical trial identifier)
  - `sponsor_id` (organization reference)

- Data cleaning operations:
  - Remove duplicates
  - Handle missing values
  - Normalize enrollment fields
  - Standardize sponsor classification
  - Assign U.S. state mapping for geographic visualization

### Load
- Processed dataset stored in-memory for dashboard rendering
- Used directly as the analytical data layer for visualizations


# 4. Dashboard Features

## 4.1 Executive KPI Layer
Displays global system metrics:
- Total clinical trials monitored
- Total participant enrollment
- Number of sponsor categories


## 4.2 Global Filter System
Interactive filtering by:
- Recruitment status
- Sponsor class
- Enrollment scale tier

Filters dynamically update all visual components.


## 4.3 Geographic Analysis (Map Visualization)
- U.S. choropleth map (Plotly)
- Displays trial distribution by state
- Click-to-filter interaction enabled
- Reset button clears selection


## 4.4 Sponsor Analysis
- Donut chart showing enrollment distribution by sponsor class
- Highlights dominance of sponsor categories


## 4.5 Master Trial Ledger
Interactive table showing:
- Protocol ID (NCT ID)
- Study title
- Recruitment status

Features:
- Row selection
- Pagination
- Linked to detailed inspection panel


## 4.6 Drilldown Inspection Panel
Displays full clinical trial profile:
- Enrollment count and scale tier
- Sponsor name and classification
- Facility location (city, state, country)
- Start and completion dates

# 6. Database Design (Conceptual Model)

Although implemented in Pandas/CSV for this project, the system is designed with a normalized relational model.


## 6.1 Sponsors Table
Stores sponsoring organizations.

| Column | Type | Description |
|------|------|-------------|
| sponsor_id | INT (PK) | Unique sponsor identifier |
| sponsor_name | VARCHAR | Name of sponsor |
| sponsor_class | VARCHAR | Classification (INDUSTRY, NIH, OTHER, etc.) |


## 6.2 Clinical Trials Table
Core clinical trial metadata.

| Column | Type | Description |
|------|------|-------------|
| nct_id | VARCHAR (PK) | Unique trial identifier |
| title | TEXT | Study title |
| recruitment_status | VARCHAR | Current trial status |
| sponsor_id | INT (FK) | Links to sponsors |
| start_date | DATE | Trial start date |
| completion_date | DATE | Trial completion date |


## 6.3 Locations Table
Stores facility-level geographic data.

| Column | Type | Description |
|------|------|-------------|
| location_id | INT (PK) | Facility identifier |
| facility_name | VARCHAR | Hospital/clinic name |
| city | VARCHAR | City |
| state | VARCHAR | State/region |
| country | VARCHAR | Country |


## 6.4 Enrollment Metrics Table
Tracks trial recruitment performance.

| Column | Type | Description |
|------|------|-------------|
| enrollment_id | INT (PK) | Record ID |
| nct_id | VARCHAR (FK) | Trial reference |
| enrollment_count | INT | Participant count |
| scale_tier | VARCHAR | Enrollment category |


## 6.5 Trial–Location Junction Table
Resolves many-to-many relationship.

| Column | Type | Description |
|------|------|-------------|
| nct_id | VARCHAR (FK) | Trial ID |
| location_id | INT (FK) | Location ID |


# 7. Entity Relationship Summary

| Relationship | Type | Description |
|-------------|------|-------------|
| Sponsors → Clinical Trials | 1 : Many | One sponsor funds multiple trials |
| Clinical Trials → Enrollment | 1 : Many | One trial can have multiple enrollment records |
| Clinical Trials → Locations | Many : Many | Resolved via junction table |
